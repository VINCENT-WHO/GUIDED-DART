基线按用户提供的 **99.8 mm** 设置。现有 YAML 只有单目内参，没有两相机间的旋转和平移；默认启用**平行光轴近似模型**：右相机光心位于左相机坐标系 `(99.8,0,0) mm`，两个相机坐标轴同向。`R=I, T=(-99.8,0,0)`，约定 `X_right=R*X_left+T`。若相机内八字、俯仰不同或有滚转，必须补做双目标定，单有基线无法确定实际外参。

## 构建和运行

在此目录的桌面终端执行（运行前关闭可能独占相机的 MVS 预览）：

```bash
cd "/home/ttt/combat飞飙/binocular vision _ranging system"
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
./build/stereo_range
```

启动时在有 `DISPLAY` 的 Linux 桌面自动选用 X11，清除当前进程继承的 GTK 路径和 schema 覆盖，避免 VS Code/Snap/Wayland 环境报 `antialiasing` schema 错误。直接运行 `./build/stereo_range` 即可，不必额外设置 `XDG_DATA_DIRS`。这不修改系统或终端全局环境。

显示 `Left camera`、`Right camera` 两幅预览，以及 `Left HSV controls`、`Right HSV controls` 两个独立调参窗口。每个相机窗口从上到下为状态栏、原图、黑白掩码，状态文字不会挡住原图；掩码默认可见，白色是通过 HSV 及形态学处理的像素，黑色是被过滤的像素。圆心坐标是 **3072×2048 原始采集图像**的像素坐标，预览缩放不参与测距。检测在原始分辨率完成。

- `q` 或 Esc：退出；也可 Ctrl+C。
- `m`：显示/隐藏相机窗口底部的二值掩码。先用鼠标点击相机画面再按英文 `m`，键盘应为英文输入状态；在终端或其他应用中按键，程序不会收到。大小写均可。默认已经显示，不必按键。
- `s`：保存当前同步请求得到的原始左右 PNG，供双目标定使用；保存位置为 `captures/left`、`captures/right`，两边文件名一致。还会保存最新标注预览和相机对应信息。
- 鼠标左键点击各自原图中的绿色圆内部（避开边缘和反光），根据 11×11 原图区域的 HSV 中位数自动设置该侧阈值，终端输出取色结果。只在原图区域点击有效。
- 两侧滑条独立调节 H 下限/上限、S 下限、V 下限、最小圆度百分数；只影响本侧。
- `w`：将两侧当前参数保存为配置文件旁的 `hsv_overrides.yaml`，下次自动加载；它优先于 `stereo_config.yaml` 中的参数。删除该文件可恢复配置文件参数。

其他命令：

```bash
./build/stereo_range --list
./build/stereo_range --csv=measurement.csv
./build/stereo_range --headless --frames=20 --save-first --csv=capture_check.csv
```

`--headless` 不创建窗口；`--frames` 不指定或为 0 时持续采集。配置文件内的路径相对于配置文件；命令行 CSV 路径相对于启动目录。采集超时等故障会报出 MVS 十六进制错误码并退出，不会把旧画面当作有效新测量。

## 检测与距离含义

SDK 将 Bayer/RGB 等像素格式转换为 OpenCV 的 **BGR**，再转 HSV，不能误用 `COLOR_RGB2HSV`。原始公共初值为 H=35–90、S≥90、V≥70（OpenCV H 范围 0–179）。2026-10-20 实拍绿色圆内部 HSV 中位数为左 (63,151,53)、右 (55,151,56)，原来的 V≥70 导致两侧掩码为空。现已增加独立参数：左 H=49–78、右 H=42–70，两侧 S≥90、V≥35，最小面积 100 像素²、最小圆度 0.60。该组参数用于当前目标和曝光，其他光照、距离下需要重新检查。

经过 3×3 椭圆核开闭运算、面积及圆度筛选，初次选择最大合格轮廓，用图像矩求中心。后续优先选择上一帧附近、面积相近的合格轮廓（中心距离不超过 max(25 像素, 3×上一帧等效半径)，面积比 0.25–4），避免在不同绿色轮廓间跳动。连续丢失 3 帧后重新捕获；丢失时不输出旧圆心，也不使用旧圆心测距。坐标和测距未做时间平滑，因此真实运动、噪声、掩码变化仍会体现在读数上。触边的残缺目标会被剔除。很远处目标若只有数个像素，可把形态学核改为 1、适当降低最小面积；噪声和中心误差也会增大。场景中应只出现一个主要绿色圆目标，其他绿色物体可能造成误匹配。

两个原始中心分别去畸变为归一化成像射线，用 `[I|0]` 和 `[R|T]` 三角化。它支持两台相机不同的焦距、主点和畸变，不直接相减原始 `u` 坐标套同焦距公式。检查正深度、射线夹角及数值是否有限；这些基本条件不满足时显示 `N/A`。重投影误差继续显示和记录，但不再参与像素门限筛选。

两个窗口中的 **`Distance to baseline: … m`** 是绿色圆心到**两相机光心所在直线的最短垂直距离**，单位 m，两窗口显示相同数值。计算对象是整条直线，不是有限线段，也不是某个光心或基线中点。`Distance to baseline: N/A` 表示目标缺失或基本可计算性检查未通过。当前显示的是未按重投影误差筛选的原始估计距离。

左坐标系中左光心为 0，右光心为 `C=-RᵀT`，绿色圆心为 `X`，距离公式为 `D=||X×C||/||C||`。当前水平平行模型下 `C=(99.8,0,0) mm`，因此 `D=sqrt(Y²+Z²)`；仅在目标与基线等高（Y=0）时等于正向深度 Z。目标不需要与基线等高。

`Left Z` 单独显示左相机光轴方向的深度，不能直接代替点到基线的距离。CSV 新增 `baseline_distance_mm` 作为主要测距结果；`left_distance_mm`、`right_distance_mm` 保留为到各自光心的辅助直线距离。距离和 Z 均以 mm 记录，无效测量留空。`APPROX parallel geometry` 表示仍使用平行近似；改变输出距离的定义不消除外参或内参引起的三维定位误差。

当前用相邻两次软件触发，再并行等待左右帧，避免自由运行相机缓存中的旧帧配对。启动时自动读取支持的 `TriggerSelector`，优先使用 `FrameStart`，也支持 `FrameBurstStart` 并设置每次一帧。实测这两台相机只提供 `FrameBurstStart`；直接设置 `FrameStart` 会报 `0x80000004`（参数错误），现已兼容。`Software trigger span` 只是两条软件触发调用的总耗时，**不是曝光时间差，也不是同步精度**。移动平板或相机可动态更新距离，但运动可能因曝光不同步产生误差；需要测量快速运动时，应进一步使用两机共同硬件触发。本程序不声称硬件同步。

## HSV 调整顺序与漏检诊断

1. 固定两台相机和目标，确认原图能看到同一个完整绿色圆，检查对焦。当前曝光为 60 ms；同曝光下，光圈、白平衡不同也会使左右颜色、亮度不同。
2. 在两幅原图中分别点击绿色圆内部自动取色，观察下面的黑白掩码。目标应该是完整、连通的白色圆斑，背景尽量黑。
3. `H min/H max` 控制色相区间。缩窄可排除其他颜色；过窄会切掉目标。绿色理想值约 H=60，但以相机实拍为准，必须保证 H min≤H max。
4. `S min` 排除灰白区域。背景白屏也变白时可提高；绿色目标因失焦、反光或低饱和而漏掉时可适当降低。纯白过曝区域无法仅靠降低阈值恢复绿色信息。
5. `V min` 排除暗背景。绿色圆全黑时适当降低；黑背景噪点过多时提高。当前实拍目标 V 约 53–56，V min=70 会全部过滤，35 留有余量。不要为了去背景把下限推到目标亮度附近，否则边缘会不断变化。
6. 掩码已有完整白圆但仍不显示中心时，看状态栏 `Rejected`：`edge` 触边，`small` 面积太小，`large` 面积过大，`shape` 圆度不足。`Circularity %` 初值 60，倾斜较大时可稍降，但过低容易把长条和噪声当作圆。面积门限仍在 YAML 中配置。
7. 两侧稳定后按 `w` 保存。按 `s` 保存原图、标注图和 `left_mask.png`、`right_mask.png`，供排查。缩小显示仍保持掩码为黑白，不做灰度插值。

`Mask empty` 表示没有像素通过分割，不是三角化失败。`Target moved / changed` 表示跟踪连续性不满足、等待重新捕获。两侧检测都显示 `OK` 后，只要基本几何和有限值检查通过就显示距离。`reproj` 仍用于观察内外参与观测的一致性，不再使距离变成 `N/A`；HSV 调整不能修正错误外参。

右侧圆心抖动需区分：十字在不同物体间大幅跳动，多与误检或轮廓切换有关；始终位于同一圆内的小幅变化，与阈值边界、失焦、噪声、屏幕变化或机械振动有关。60 ms 曝光下运动还会造成拖影。当前使用真实逐帧中心，不通过平滑隐藏误差。

可以使用已保存原图离线调参（不会打开相机）：

```bash
./build/stereo_range --left-image=captures/left/同名图片.png --right-image=captures/right/同名图片.png
```

## 补做双目外参标定

固定好相机后，在两台相机共同视野内摆放实际尺寸已知的棋盘格（不是单个绿色圆）。保持焦距、对焦、分辨率、ROI、binning 和相机安装姿态与测距时一致。

1. 运行 `stereo_range`，用 `s` 保存至少 10 对、建议 15–25 对清晰的棋盘格图像。拍摄时棋盘格停稳，改变位置、距离和倾角，覆盖共同视野。不要把不同相机顺序或不同安装姿态的图像混在一起。
2. 执行下面的标定命令；9×6 是**内角点数量**，18 mm 是示例物理格长，必须按实际值修改。如果在屏幕上显示棋盘格，要实际测量屏幕上的格长。

```bash
./build/stereo_calibrate --pairs=captures --cols=9 --rows=6 --square-mm=18 --output=stereo_extrinsics.yaml
```

3. 查看终端 RMS、求出的基线和 `captures/corners` 中的左右角点对应可视化。工具固定现有内参，估计两相机 R/T；少于 10 对或总 RMS 超过 2 px 时拒绝输出。较小 RMS 也不等于已验证的绝对测距精度。普通棋盘格存在方向歧义，此工具面向相对滚转小于 90° 的常见左右安装。
4. 把 `stereo_config.yaml` 的 `extrinsics: ""` 改为 `extrinsics: "stereo_extrinsics.yaml"`，重启测距。外参优先于近似基线配置。标定文件写入相机序列号，运行时会检查对应顺序；移动相机或改变对焦后应重新评估标定。

原有两个内参文件不会被覆盖；外参输出文件已存在时，工具要求换一个输出文件名。

## 采集与精度检查

2026-10-20 验证：直接运行已修复 GTK 启动问题的程序，离线图像窗口测试正常；黑白掩码默认拼接在各自原图下方。真实目标连续 60 对画面中，左右各检测到 60/60 帧，横坐标标准差左 0.31 px、右 0.43 px；纵坐标标准差均约 4.1 px，左右纵向变化相关系数 0.998。这提示存在共同运动，不能据此证明相机或目标已静止，也不能据此认定测距精度。

在此前启用 2 px 门限的版本中，该批次距离有效帧为 0/60，原因是平行外参模型下重投影检查失败。识别成功不代表几何模型正确，应核实安装外参和当前焦点下的内参，建议棋盘格双目标定；显示估计值并不表示误差已消除。上述历史诊断图片、CSV 和测试程序已在工作区清理时删除；保留此处结论供排查参考。

程序保留相机当前 ROI、binning、像素格式和白平衡。帧尺寸必须与内参的 3072×2048 一致，且 ROI 原点、binning、翻转和校准时的设置也必须一致；仅凭尺寸无法验证这些项目。当前按用户要求设置 `exposure_us: 60000.`，启动时两台相机均关闭自动曝光，设置为 **60000 μs = 60 ms = 0.06 s**，并在终端输出读取到的曝光值。配置单位是微秒，不是秒；改为 0 则保留相机当前曝光配置。若平板过曝导致绿色接近白色，先降低曝光或屏幕亮度。相机必须是彩色相机，黑白图像无法使用色相分割。

如果报打开失败，检查是否被 MVS 等进程占用；如果枚举失败，检查 USB 接口、驱动和权限；如果超时，检查线材、供电、USB 带宽及曝光。程序退出时停止采集并关闭触发模式，不调用持久化相机参数保存。

远距离时应使用足够大的目标、清晰对焦及短曝光。99.8 mm 基线下远处视差变小，微小角度偏差和亚像素中心偏差会明显影响测距。先对几个已知实测距离验证偏差和重复性，再判断是否满足要求；大倾角的平面圆形，其图像面积中心也可能偏离物理圆心的投影。


## 为什么仍显示 N/A，以及如何阅读源码

当前版本已去掉测距时的 2 px 重投影门限，满足基本条件就显示点到基线的原始距离估计。`N/A` 仍可能由以下目标缺失或几何退化原因产生。

- `Target missing: LEFT/RIGHT`：所列相机没有检出合格圆心，先检查原图、HSV 掩码及轮廓诊断。
- `NO EXTRINSICS`：既未加载外参，也没有可用的平行模型基线。
- `Too little parallax`：两条射线夹角小于配置门限，深度不稳定。
- `Behind camera`：三角化点落到某台相机后方，需核对左右顺序和 R/T。
- `Nonfinite result`：计算出现非有限数值，无法输出距离。
- `reproj=… px`：仅显示回投影残差，不再设置上限。终端和 CSV 同时保留该数值，供实测比较和后续拟合使用。

此前使用 99.8 mm 基线对保存的目标图片离线复算时，两侧圆心均检测成功，但回投影误差为 **78.18 px > 2.00 px**，所以在旧版门限下距离无效（此前另一组观测约为 77 px）；新版会显示该类观测的可计算估计值。当前 `extrinsics` 为空，实际采用 `R=I、T=(-99.8,0,0) mm`。这说明该组观测与此模型不一致，但仅凭一个残差不能断言一定是哪一个参数错误。优先检查相机安装的相对角度、上下/前后错位、左右内参对应关系，以及调焦后内参是否仍适用。建议在当前固定安装和对焦状态下拍摄棋盘格对，固定可信内参估计真实 R/T；若内参已不适用，应先重新验证/标定内参。当前版本按用户要求显示未筛选估计，仍需用已知距离评估偏差和重复性。

## 2026-10-21 去掉测距重投影门限

已从核心函数、调用参数和配置中移除测距的 `max_reprojection_error_px`。重投影误差无论是否超过原来的 2 px，都不会仅因此隐藏距离；窗口中的 `Distance to baseline` 显示到两光心直线的原始估计距离（m），`reproj` 仍显示像素残差。终端和 CSV 保留距离、残差及 `Estimate (reprojection not filtered)` 状态，方便后续与真实距离对照。CSV 的 `valid=1` 仅表示目标齐全、正深度、射线夹角足够且数值有限，不代表精度已经验收。

目标缺失、视差不足、无效基线、点位于相机后方及非有限结果仍返回 `N/A`。此改动不调整双目外参标定工具的 `--max-rms` 参数，它只影响未来标定结果的保存判定。
